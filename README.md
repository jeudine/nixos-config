# nixos-config

Flake-based NixOS configuration for a single headless machine: the host `server`.

## Layout

| File | Purpose |
| --- | --- |
| `flake.nix` | Inputs (nixpkgs 26.05, [claude-code-nix](https://github.com/sadjow/claude-code-nix)) and the `nixosConfigurations.server` output |
| `configuration.nix` | The actual system config: bootloader, networking, users, services, packages |
| `hardware-configuration.nix` | Generated by `nixos-generate-config`; filesystems, kernel modules, CPU. Do not edit by hand |
| `flake.lock` | Pinned revisions of all inputs |
| `update.sh` | Update inputs, rebuild, commit the new lock |

## What the system provides

- **Boot**: systemd-boot on UEFI.
- **Storage**: btrfs, a `tank` filesystem with `data` and `workspace` subvolumes, scrubbed monthly. See [Storage (btrfs)](#storage-btrfs).
- **Host**: `server`, timezone `Europe/Zurich`, `x86_64-linux`.
- **User**: `julien`, normal user in the `wheel` group (sudo). No password is set here — set one with `passwd` or add `users.users.julien.openssh.authorizedKeys.keys`.
- **SSH**: `openssh` enabled with password authentication disabled, so key-based login only.
- **mDNS**: `avahi` publishing addresses, so the box is reachable as `server.local`.
- **Nix**: `nix-command` and `flakes` experimental features enabled.
- **Packages**: `git`, `vim`, `htop`, and `claude-code` (unfree, allowed via `allowUnfreePredicate`).

## Usage

Clone somewhere on the machine (this repo lives in `~/nixos-config`, not `/etc/nixos`):

```bash
git clone <this-repo> ~/nixos-config
cd ~/nixos-config
```

Apply the configuration:

```bash
sudo nixos-rebuild switch --flake .#server
```

Test without making it the boot default:

```bash
sudo nixos-rebuild test --flake .#server
```

Build only, to check that it evaluates:

```bash
nixos-rebuild build --flake .#server
```

## Storage (btrfs)

`configuration.nix` mounts two subvolumes from the btrfs filesystem labelled
`tank`: `data` at `/data` and `workspace` at `/workspace`. Both sit at the top
level of the filesystem, not inside each other.

To create them, first find the partition to use. **Everything on it will be
erased.**

```bash
lsblk -o NAME,SIZE,FSTYPE,LABEL,MOUNTPOINT
```

Then, replacing `/dev/sdX1` with that partition (e.g. `/dev/sdb1`,
`/dev/nvme0n1p3`):

```bash
nix shell nixpkgs#btrfs-progs    # btrfs tools aren't installed until the first rebuild
sudo mkfs.btrfs -L tank /dev/sdX1
sudo mkdir -p /mnt
sudo mount /dev/disk/by-label/tank /mnt
sudo btrfs subvolume create /mnt/data
sudo btrfs subvolume create /mnt/workspace
sudo umount /mnt
sudo nixos-rebuild switch --flake .#server
```

`mkfs.btrfs` refuses to overwrite a partition that already holds a filesystem.
If it does, and you are sure the data can go, clear it with
`sudo wipefs -a /dev/sdX1` and run `mkfs.btrfs` again.

The partition only appears in the `mkfs.btrfs` step: after that everything
goes through the `tank` label, which is also what `configuration.nix` mounts.
No other change to the config is needed. The label and the subvolume names
must match the `fileSystems` entries there, and the mount points are created
automatically.

## Updating

`update.sh` wraps the update-rebuild-commit cycle. It refuses to run with a dirty
working tree, and does nothing if `flake.lock` comes back unchanged.

```bash
./update.sh                # update every input
./update.sh claude-code    # update a single input
```

The script derives the flake attribute from `hostname`; override it with
`HOST_OVERRIDE=server ./update.sh` if the machine's hostname ever differs from
the `nixosConfigurations` name.

To roll back an update:

```bash
git revert HEAD
sudo nixos-rebuild switch --flake .#server
```

Previous generations are also available from the systemd-boot menu, or via
`sudo nixos-rebuild switch --rollback`.

## Adding a new machine

1. Run `nixos-generate-config --no-filesystems` on the new host and copy its
   `hardware-configuration.nix` into a per-host directory.
2. Add a matching `nixosConfigurations.<hostname>` entry in `flake.nix`.
3. Move anything shared out of `configuration.nix` into a common module.
